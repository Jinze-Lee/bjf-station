# 观测数据接口规范 v1

> 这是你给我数据、或以后自行上传数据时要遵守的格式。
> 不管最终用哪种上传方式（本地脚本 / 静态托管 / 真后端），**这个格式都不变**。

---

## 一、总则

| 项 | 规定 |
|---|---|
| 文件格式 | CSV，**UTF-8 编码**（Excel 另存时选「CSV UTF-8」） |
| 表结构 | **长表**（每行一个观测值），不是宽表 |
| 换行 | 无所谓，`\n` 或 `\r\n` 都行 |
| 首行 | 必须是表头，列名小写，顺序不限 |
| 缺测 | **整行不写**。不要填 `NA` / `-9999` / 空字符串 |

**为什么用长表而不是宽表**：20 棵树 × 2 个变量 = 40 列的宽表，一旦增减树木或传感器就要改表结构，
而且某棵树掉线时整行都要补空。长表加树只是多几行，掉线就是少几行，不动结构。

---

## 二、列定义

| 列名 | 必填 | 类型 | 说明 |
|---|:---:|---|---|
| `tree_id` | ✅ | 文本 | **必须与 `js/trees.js` 里的编号完全一致**，见第五节清单 |
| `timestamp` | ✅ | 文本 | ISO 8601，**必须带时区偏移**，见第三节 |
| `variable` | ✅ | 文本 | `sap_flux_density` 或 `stem_radius`，见第四节 |
| `value` | ✅ | 数字 | 十进制，小数点用 `.`。不要带单位、不要带千位分隔符 |
| `quality` | ⬜ | 文本 | `ok` / `suspect` / `bad`，不写默认 `ok`。标 `bad` 的点不会画上图 |

### 最小示例

```csv
tree_id,timestamp,variable,value
DT3-SY2-1138,2026-07-13T00:00:00+08:00,sap_flux_density,3.42
DT3-SY2-1138,2026-07-13T00:00:00+08:00,stem_radius,21089.4
DT3-SY2-1138,2026-07-13T00:30:00+08:00,sap_flux_density,3.15
DT3-SY2-1138,2026-07-13T00:30:00+08:00,stem_radius,21091.2
```

### 带质量标记的示例

```csv
tree_id,timestamp,variable,value,quality
DT1-BH1-1137,2026-07-13T12:00:00+08:00,sap_flux_density,41.2,ok
DT1-BH1-1137,2026-07-13T12:30:00+08:00,sap_flux_density,998.7,bad
```

## 三、时间戳 —— 最容易出错的一项

**必须写成 ISO 8601 并带上时区偏移**，北京时间就是 `+08:00`：

```
2026-07-13T14:30:00+08:00     ✅ 正确
2026-07-13 14:30:00           ❌ 没有时区，会被当成 UTC，整体差 8 小时
2026/7/13 14:30               ❌ 格式不对
1752384600                    ❌ 不接受 Unix 时间戳
```

> ⚠️ **这一条错了，全部曲线会整体平移 8 小时**，昼夜节律会看起来完全不合理
> （液流峰值跑到半夜）。导入脚本会强制检查，缺时区直接报错不放行。

**Excel 用户注意**：Excel 的日期单元格另存为 CSV 时通常丢掉时区。
稳妥做法是把该列设为**文本格式**，直接写完整字符串。

采样间隔不必固定，也不要求各棵树对齐——图表用的是真实时间轴（`ordinal: false`），
数据有空缺就如实显示空缺。

## 四、变量与单位

| `variable` 取值 | 含义 | **必须使用的单位** | 建议小数位 |
|---|---|---|---|
| `sap_flux_density` | 液流通量密度 F<sub>d</sub> | **g m⁻² s⁻¹** | 2 |
| `stem_radius` | 径向变化仪的**原始位移读数** | **μm** | 1 |

> ⚠️ `stem_radius` 存的是传感器原始读数，**零点由安装位置决定，绝对值本身没有意义**
> ——同一片林子里有的树读数 500 μm、有的 174000 μm，纯粹取决于装的时候旋到哪一格。
> 网页按每条记录的**首个点归零**后显示为「径向变化量」，这也是 dendrometer 文献的标准画法。
> 所以你**不需要**、也**不应该**自己去减基线；照原样给读数即可。

### 如果你的原始数据不是这个单位

**不要自己换算**，在 `meta.json`（见第六节）里声明原始单位，导入脚本会换算并留痕。
支持的换算：

| 变量 | 可声明的原始单位 |
|---|---|
| `sap_flux_density` | `g m-2 s-1`（规范）、`kg m-2 s-1`、`cm3 cm-2 s-1`、`dm3 dm-2 h-1` |
| `stem_radius` | `um`（规范）、`mm`、`cm` |

### 想加新变量？

比如加气温、土壤含水量、土壤 CO₂、树木水分亏缺 TWD，告诉我变量名与单位，
我在前端加对应的坐标轴与曲线。**格式本身不用改**，直接多写几行即可。

## 五、tree_id 清单（必须完全一致，区分大小写）

|---|---|

## 六、随数据附一个 meta.json（可选但建议）

放在与 CSV 同一目录，记录这批数据的来源与口径：

```json
{
  "batch": "2026-07-13_to_2026-07-27",
  "produced_at": "2026-07-28T10:00:00+08:00",
  "produced_by": "Li Jinze",
  "source": "dataTaker DT80 导出 + 各径向变化仪独立回传",
  "timezone": "Asia/Shanghai",
  "units": {
    "sap_flux_density": "g m-2 s-1",
    "stem_radius": "um"
  },
  "notes": "DT2-LYS1 于 7 月 20 日更换电池，当日 09:00–11:00 数据已剔除"
}
```

`units` 里写你 CSV 里**实际使用**的单位；与规范单位不同时，导入脚本会自动换算。

## 七、文件命名与分批

```
数据/
├── 2026-07-13_2026-07-27_观测数据.csv
├── 2026-07-13_2026-07-27_meta.json
├── 2026-07-28_2026-08-10_观测数据.csv
└── 2026-07-28_2026-08-10_meta.json
```

- 文件名格式：`起始日期_结束日期_观测数据.csv`
- **可以分多次上传**，导入脚本会把所有批次合并、按时间排序、按
  `(tree_id, timestamp, variable)` 去重（后上传的覆盖先上传的）
- 单个文件建议不超过 50 MB

## 八、体量参考

按当前配置（20 棵树 × 2 变量 × 30 分钟间隔）：

| 时间跨度 | 行数 | CSV 大小 |
|---|---:|---:|
| 1 天 | 1 920 | ~110 KB |
| 1 个月 | 57 600 | ~3.3 MB |
| 1 年 | 700 800 | ~40 MB |

超过约 3 个月的数据全量塞进网页会明显变卡。届时前端要改成**按需分段加载**，
到时候告诉我，格式不用变。

---

## 九、导入脚本会检查什么

`python 工具/校验观测数据.py <csv路径>` 会逐条检查并给出行号：

1. 表头是否含全部必填列
2. `tree_id` 是否在清单内（拼错、多空格、大小写不符都会报）
3. `timestamp` 是否可解析、**是否带时区**
4. `variable` 是否为已知取值
5. `value` 是否为数字、是否落在合理量程内（超出会警告不会拦）
6. 是否有重复的 `(tree_id, timestamp, variable)` 组合
7. 各棵树的时间覆盖范围与缺测比例

**校验通过前不要上传**——脏数据进了展示层，比没数据更糟。
