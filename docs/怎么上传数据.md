# 怎么上传数据（操作手册）

> 三步：**放文件 → 跑脚本 → 刷新网页**。不需要服务器，不需要联网。

---

## 一、日常流程

### 第 1 步：把 CSV 放进 `数据/` 目录

```
E:\网页制作\数据\
├── 2026-07-13_2026-07-27_观测数据.csv     ← 你的数据
├── 2026-07-13_2026-07-27_meta.json        ← 可选，说明批次来源
├── 示例_观测数据.csv                       ← 格式样例，会被自动跳过
└── 示例_meta.json
```

格式见 **`docs/数据接口规范.md`**。文件名以 `示例_` 开头的会被跳过。

### 第 2 步：跑导入脚本

```powershell
python "E:\网页制作\工具\导入观测数据.py"
```

脚本会自动：校验 → 换算单位 → 剔除 `quality=bad` → 多批次合并去重 → 写出 `js/observations.js`

**有任何错误就不写文件**，避免脏数据进展示层。

### 第 3 步：刷新网页

浏览器按 `Ctrl + F5` 强制刷新。图表、下拉框、地图全部自动跟着变。

---

## 二、上传后网页会有哪些变化

| 变化 | 说明 |
|---|---|
| 橙色「演示数据」警示条**自动消失** | 换成绿色信息条，列出时间范围、观测点数、批次清单 |
| 图表换成你的数据 | 时间轴自动适配你的数据范围 |
| 没有数据的树**自动标灰** | 下拉框里禁选并标注「本批无数据」，地图上画成空心圈 |
| 默认展示的树 | 若 DT3-SY2-1138 无数据，自动退回第一棵有数据的树 |

这些都不用手工改文案——**页面读 `OBS_META.source` 自己判断**，
所以不会出现「数据早换成实测了，页面还挂着演示警示条」这种情况。

## 三、常用操作

### 只想先看看数据有没有问题，不写文件

```powershell
python "E:\网页制作\工具\导入观测数据.py" --dry-run
```

### 单独校验某个文件（会报到行号）

```powershell
python "E:\网页制作\工具\校验观测数据.py" "E:\网页制作\数据\你的文件.csv"
```

### 切回合成示例数据

```powershell
python "E:\网页制作\工具\生成示例数据.py"
```

会覆盖 `js/observations.js`，橙色警示条重新出现。

### 补发修正版数据

把修正后的文件**用更靠后的文件名**放进 `数据/` 再重跑导入即可。
合并时按 `(树号, 时间戳, 变量)` 去重，**后导入的覆盖先导入的**。
原始文件不用删，留着可追溯。

## 四、单位不对怎么办

**不要自己换算**。在 `meta.json` 里声明你 CSV 的实际单位，脚本会换算并在日志里留痕：

```json
{ "units": { "sap_flux_density": "cm3 cm-2 s-1", "diameter": "mm" } }
```

支持：

| 变量 | 可声明的单位 |
|---|---|
| `sap_flux_density` | `g m-2 s-1`（规范）、`kg m-2 s-1`、`cm3 cm-2 s-1`、`dm3 dm-2 h-1` |
| `diameter` | `cm`（规范）、`mm`、`um`、`m` |

不在表里的单位会直接报错，不会静默算错。

## 五、时区（最容易出错，单独说）

CSV 里的时间戳**必须带 `+08:00`**：

```
2026-07-13T14:30:00+08:00   ✅
2026-07-13 14:30:00         ❌ 校验器会拦下
```

页面按 **UTC+8** 显示（`chart.js` 里的 `time.timezoneOffset: -480`）。
验收测试里有一条专门盯这个：**平均日变化的峰值必须落在当地 11–14 时**，
时区配错的话这条会直接失败。

> 为什么用「平均日变化峰值」而不是「最大值时刻」来验：液流日变化是**平台状**的，
> 白天十来个小时几乎等高，叠加噪声后单点最大值会随机落在平台任意位置，
> 用它判断时区会误报。

## 六、数据量的现实限制

当前是把全部数据打包进一个 JS 文件，浏览器一次性载入。

| 时间跨度 | `observations.js` 大小 | 体感 |
|---|---:|---|
| 14 天（现在） | 0.6 MB | 秒开 |
| 1 个月 | ~1.3 MB | 正常 |
| 3 个月 | ~4 MB | 首次加载略慢 |
| 1 年 | ~15 MB | **明显卡**，需要改架构 |

超过约 3 个月时导入脚本会提示。届时要改成**按需分段加载**
（只载入当前视窗那段），到时候告诉我，**数据格式不用变**。

## 七、以后想换成真正的网页上传怎么办

现在是「本地脚本」方案。以后若要升级成浏览器里点上传，路径是通的：

| 阶段 | 要做什么 | 数据格式 |
|---|---|---|
| **现在**：本地脚本 | 无 | 不变 |
| 升级 A：静态托管 | 前端改成 `fetch('data/*.json')`，上传 = 传文件到网空间 | **不变** |
| 升级 B：真后端 | Flask/FastAPI + 登录 + 上传表单 + 数据库 | **不变** |

**关键是格式和校验器在三个阶段完全复用**，只有「最后一公里」不同。
所以现在按规范准备数据不会白做。

升级 A 有个副作用要注意：改成 `fetch` 后**双击本地文件就打不开了**
（浏览器 CORS 限制），必须走 HTTP。届时要权衡。
