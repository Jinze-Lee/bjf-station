## 判断依据

| 类型 | 规则 | 呈现 |
|---|---|---|
| 已确认故障 | 来自预处理脚本的人工核实故障段；异常原始读数不作为设备恢复的证据 | 红色呼吸感叹号、已确认故障 |
| 批次末缺测 | 每 30 分钟采样，至批次末连续缺少至少 2 次预期记录 | 橙色呼吸感叹号、待核查 |
| 整批无数据 | 本批没有有效记录，且没有人工确认故障的证据 | 橙色、待核查 |
| 缺测后恢复 | 批次内部连续缺少至少 2 次记录，随后有有效记录 | 历史记录 |
| 已订正阶跃 | 预处理脚本中已有人工核实、订正的读数阶跃 | 历史记录 |

液流为零、径向短期收缩或单次漏采不会直接判为故障。第一版没有给生理变化幅度设置未经核实的故障阈值。缺测原因不会自动写成断电、掉线或电池不足。

## 使用

1. 点“设备报警”：展开列表并显示异常点位的呼吸光圈，图层面板同时避让。
2. 点列表中的设备：镜头平滑定位并显示详情。直接点击感叹号也可打开详情。
3. 点“历史记录”：查看已恢复、已订正事件；定位历史点时显示静态橙色定位标记。
4. 点“查看监测数据”：沿用原来的曲线窗口，并选中对应树号。
5. 关闭报警入口、关闭面板或按 Esc，可退出报警查看。曲线窗口打开时 Esc 先关闭曲线。

感叹号放在 #labels 的 DOM 层，随相机投影更新。报警独立于普通名称和设备图层显隐；切去其他台站时隐藏本站报警标记，点击定位可返回本站。遵循浏览器的“减弱动态效果”偏好。

数据加载失败时入口显示 !，面板提供重试，不显示“0 个异常”。

## 文件及更新

- 工具/生成设备报警.py：生成批次快照，仅使用公开观测和已有故障/订正配置。
- 3d/alarms.json：快照、规则、溯源及各通道统计，不包含全量观测值。
- 3d/alarms.js、3d/alarms.css：面板、场景标记和交互。
- 工具/验收测试_报警.py：数据规则及真实 Chrome 交互验收。

更换公开批次后运行：

    python 工具/生成设备报警.py

脚本会检查实测标记、20 点映射、观测总数、时间范围和时间顺序；只写报警快照，不修改原始或已发布的监测值。已确认故障在没有明确核实修复之前保持报警，原始异常读数不自动视为恢复。

验收：

    python 工具/本地预览服务.py 8000
    # 另一个终端
    python 工具/验收测试_报警.py

现有本地预览服务没有实现点云需要的 HTTP Range。报警验收通过仅在测试浏览器内生效的路由提供正确分段内容，不修改预览服务器。原有 sources.json 404、图表验收脚本的数组下标问题不属于本次改动。
